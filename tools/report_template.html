Silence is not absence — these counts are a floor

Every number here comes from a moment the user said something. In their words: “I dont always share my feedback, and so there are times i may consider these worse than this report identifies.” Four patterns were named as undercounted: incomplete, wrong_approach, inefficient_process, and lost_context.

That is a structural bias, not a guess. A method built on corrections can only see failures whose natural response is pushback. Failures whose natural response is silent accommodation — restating a fact Claude already forgot, waiting out a flailing retry loop, quietly finishing the half of the task Claude skipped — leave no trace in the corpus at all. lost_context shows 5 incidents here; the honest reading is that 5 is how often it annoyed the user enough to mention, not how often it happened.

The two findings in this report that do not depend on the user speaking up — the commit-length gap and the comment-replacement shrink — are both worse than anything the correction data surfaced. That is the pattern to expect.

What this says to build

The comment measurement was wrong, and the user caught it

An earlier draft reported a 15.6% comment fail rate and concluded the comment hook should not ship. The user's response: “I have re-worded your overly verbose comments many times.” The number does not survive that, for three compounding reasons.

The corpus double-counts corrections. It is built from Claude's own Edit and Write calls, so a bloated comment and its fix are both in it, and every fix scores as a fresh good comment. The rubric could not see verbosity — it asks what-vs-why and unstated-premise, never “is this three times longer than it needs to be”. Editor-side rewording is invisible — a transcript sweep only sees edits that passed through a tool call.

Corrected position: comment verbosity is real and repeated, and what_not_why alone will not catch it. Whether enforcement is a rule or a hook is still open — but “do not ship it” was the wrong call.

Nothing came back hook-shaped, and that may be the judges' fault

Of {{CONFIRMED}} confirmed findings the judges marked 163 fixable by a rule and only 3 by a hook. Either these failures genuinely are rule-shaped, or the judges took the cheaper answer. This data cannot separate those, and the same rubric family just proved fallible on comments.

The strongest lead was found before the sweep ran

The existing writing-style skill ends its description with “Do NOT use for code, commit messages, or internal notes” — and it is manually invoked, so nothing fires it when Claude writes a commit message mid-task. The {{RATIO}}× length gap is what that looks like in the data. The rules may be fine; nothing triggers them.

Method, and where it is thin

Finders cast wide, judging cut hard. Structural signals — a short message right after a long assistant turn, a negation-leading message, profanity — surfaced 1,080 candidates from 2,190 of the user's messages. Triage kept 325. A second pass read the full surrounding conversation and confirmed {{CONFIRMED}}, killing the rest for pointing at a vendor, a tool, or the user themselves rather than at Claude.

Profanity finds, it does not rank. the user's swearing rate quadrupled on 2026-07-20 and is four times higher in Claude Code than in chat. Weighting severity on it would have buried everything earlier and most of the chat corpus.

Coverage is complete, but three stages needed repair. The triage model silently dropped 19 of 1,080 items while reporting full counts; the judges dropped 2 of 325. Both were backfilled by hand. The comment extractor first emitted one item per comment line, which would have length-weighted the fail rate — 2,546 fragments were regrouped into 852 blocks and re-judged.

A judged rate is only as good as its rubric. The comment pass is the proof: a clean-looking 15.6% collapsed the moment it met comments Claude had itself replaced. Any number here resting on a model's opinion carries that risk.

What this cannot see. Everything the user absorbed without saying so. Failures inside subagent transcripts, excluded. Repos with a separate upstream remote, excluded because the user curated those themselves. And of 852 authored comment blocks only 384 could be checked against a live working tree; the rest live in worktrees since deleted.
