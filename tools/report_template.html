Silence is not absence — these counts are a floor

Every number here comes from a moment the user said something. That is a structural bias, not a guess. A method built on corrections can only see failures whose natural response is pushback. Failures whose natural response is silent accommodation — restating a fact Claude already forgot, waiting out a flailing retry loop, quietly finishing the half of the task Claude skipped — leave no trace in the corpus at all.

An incident count is therefore how often a failure was worth complaining about, not how often it happened. Any pattern whose natural response is silence is undercounted here by construction. The measured signals further down need no complaint to fire, and exist as the check on exactly that.

Every confirmed incident

{{CONFIRMED}} episodes in {{PATTERNS}} patterns, ordered by episodes × median severity. Patterns needing a rule are expanded; the rest are collapsed. Within each pattern, noncompliant episodes come first, then descending severity. Noncompliant means an instruction already existed and was not followed — said earlier in the session, written into a config or convention, or established in an earlier one. It is narrower than “happened more than once”, and it is what separates a pattern needing a standing rule from one a single correction resolves: if instructions were already in place and were broken anyway, advice has demonstrably failed. Severity is derived only from era-stable signals: how long the user sat through before objecting, how much work rested on the mistake, whether the thread was abandoned, whether it had already been said. Where one argument spans several messages they are merged and tagged “N write-ups, one moment”, with the other quotes shown underneath the first.

Method, and where it is thin

Finders cast wide, judging cut hard. Structural signals — a short message right after a long assistant turn, a negation-leading message, profanity — surfaced {{CANDIDATES}} candidate windows. Triage promoted {{TRIAGED}}. A second pass read the full surrounding conversation and confirmed {{RAW}}, killing the rest for pointing at a vendor, a tool, or the user themselves rather than at Claude.

Profanity finds, it does not rank. Swearing rates drift over time and differ by interface, so weighting severity on them would bury whichever era or corpus happened to be politer.

Only a shared quote proves a duplicate. Judges sometimes write up one message twice, and resuming a session replays earlier messages into a second transcript. Merging incidents that merely sit close together in one session under the same label assumes they are one argument, and that assumption does not hold — proximity means two things went wrong near each other, not that one thing went wrong. Merging is on identical quote alone: {{RAW}} confirmed incidents collapse to {{CONFIRMED}}, and the merge keeps the worst member so a repeat flag can never be lost to merge order.

The user's rulings outrank the judges'. The judges are a rubric applied by a model; the user is the person the rules are for. Where they have corrected a finding it is marked Corrected by the user, their wording replaces the judges', and it survives a re-run via overrides.json.

A coarse label hides which rule would help. A single kind holding dozens of episodes cannot say what to fix. Where hand review splits one into distinct failures, the sub-kinds replace it and the ruling on the parent is inherited by them.

Noncompliance detection is a finder plus a review, not a pattern match. It decides which patterns need a rule, so a missed one changes the answer. Lexical matching on phrases meaning “I already told you” has poor precision — many matches mean the opposite, and a typo defeats character matching outright. So the pattern is a finder only, and a review pass reads the full context around each candidate, which handles typos for free by reading meaning.

A judged rate is only as good as its rubric. A rubric that never asks whether something is three times longer than it needs to be cannot report verbosity, no matter how clean the resulting percentage looks. Any number here resting on a model's opinion carries that risk.

What this cannot see. Everything the user absorbed without saying so. Failures inside subagent transcripts, excluded. Repos configured as excluded, and comments whose files no longer exist on disk.
